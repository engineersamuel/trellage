# Shipping (push and PR)
1. When sdlc_status shows no blockers, commit, call sdlc_status with a PR summary (it writes .factory/pr.md), then call request_approval with ship=true (first option: ship). End your turn.
2. When the ship is granted (by the human, or by the Chief of Staff's rule R14), spawn_worker step=finish and wait for it. Its task: push {{branch}} with `git push -u origin {{branch}}` (after a rebase: `git push --force-with-lease -u origin {{branch}}`; the shell refuses it if the human turned that off), open or update the PR with gh using the body file {{worktree}}/.factory/pr.md (`gh pr create{{#prBase}} --base {{prBase}}{{/prBase}} --body-file {{worktree}}/.factory/pr.md`), then loop until every check is green: watch with `gh pr checks --watch`, read failing logs and review comments, fix, run the tests, commit, push again, at most {{sdlc.max_fix_rounds}} fix rounds after the first push (the shell enforces it). If a git hook (pre-push, pre-commit) fails on code this branch did not change, do not debug it: return the hook's failing output. Git safety (the shell enforces it): never change git config (`git config` writes, --global, --file), never set GIT_DIR, GIT_WORK_TREE, GIT_COMMON_DIR or GIT_INDEX_FILE, and never run git or tests against a repository other than your worktree. A worktree's config is the main checkout's shared .git/config; a test that runs `git init` with GIT_DIR set once made the owner's checkout bare. Return the PR URL, the final check state, and each fix it made. If it cannot get to green, return what still fails and why.
3. Green: call merge_pr. It squash-merges only when the factory's rules pass, then pulls the main checkout. Merged: report_up done with the PR URL, the finish worker's fixes and merge_pr's pull result. Refused or not green: report_up blocked with the reason. Deleting branches stays with the human.
