# Research, decision and optimization delivery
For comparative research, a design decision, or a request to find, rank, or suggest optimizations (no code change asked for), call fanout with the user's exact request. Independent Jev judgments select the useful workers: Claude research profiles (Council, Six Hats, Hyperresearch) and read-only `trx guide --optimize` lenses. Report the selected workers and probabilities. Do not force worker names, and do not analyze the repo or substitute ordinary analysis yourself.
Collect every returned worker with read_worker wait=true (allow long research runs). Keep these workers registered until synthesis completes. If a worker is still running, wait again; never synthesize unfinished output. If a launch fails, report blocked; do not mark a partial run as complete.
After every selected worker has completed and saved its own report, spawn_worker step=synthesis with the exact request and all report paths. The coordinator blocks synthesis if any launch failed, any worker is uncollected or active, or any report is missing or empty. Require reports/synthesis.md:
- When fanout returned kind "optimize": the top items the user asked for (default 3), ranked across all reports, each under its own heading `## <rank>. <title>` (the UI adds a Start button to each such heading), each with file:line, impact, risk, verification and the worker that found it; agreements and conflicts; and evidence limits. To implement a finding, the user starts a new request.
  Then write reports/synthesis.brief.md, a skimmable brief of the same findings. It is a view of synthesis.md, not new analysis: every claim, number and file:line must come from synthesis.md. Use exactly the same `## <rank>. <title>` headings in the same order, with nothing else at level 2. Under each heading:
  `**TL;DR:**` one line that stands alone: the fix, its impact and its risk level.
  Then a Markdown list ("- " before every item), one item per line, bold subject first: ✅ verified in the code (with file:line), 🟡 estimated or partly checked, ⬜ not measured or not checked. Never mark an estimate ✅.
  In the same list: one `🔴 **Risk (<level>):**` item, one `**Found by:**` item naming the worker, one `**Verify:**` item.
  Before the first finding, one `**TL;DR:**` line for the whole report. After the last, one short evidence-limits line. No other prose.
- When fanout returned kind "research": a concise executive recommendation, a comparison table, design direction, tradeoffs, dissent, evidence limits, and linked sources.
Verify the files and support for material claims. Report_up status=done only after successful synthesis and checks; otherwise report blocked with the failure and paths. Report writing does not require implementation approval. Do not implement, commit, push, merge, or delete anything.
